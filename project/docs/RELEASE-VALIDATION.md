# Host release validation, 2026-10-03

Measured results are in [release-validation.json](../release-validation.json). No device operation, push or remote creation occurred. Source evidence was read at b27485515; the source repository remains unchanged.

Linux 6.6.157 was downloaded from kernel.org and its uncompressed tar signature verified using Greg Kroah-Hartman's key acquired through kernel.org WKD. Fingerprint: `647F28654894E3BD457199BE38DBBDC86092693E`, checked against the [official signature instructions](https://www.kernel.org/signature.html). Official barebox 2026.09.0 MD5 passed; SHA256 is pinned, and all release file contents, modes and symlinks match v2026.09.0 git archive. The official mmc-utils snapshot matches all 24 legacy source files/modes; the container hash was updated rather than publishing a locally generated archive.

Two fresh kernel tarball trees/build directories produced byte-identical zImage and DTB matching the deployed hashes (`5c666c72…` / `8960edb8…`). Two fresh barebox tarball builds produced the exact deployed v8 (`b283f374…`). The USB DCD reference was independently source-built with unchanged upstream/stock ZQ 23/8; the plugin built using the existing stock boot0 backup header also matched v8. No binary reference is required by the public command beyond the user's boot0 header input.

With `-ffile-prefix-map`, `-fdebug-prefix-map`, fixed SOURCE_DATE_EPOCH and `--build-id=sha1`, wpa_supplicant, wpa_cli and iw are each byte-identical across two fresh source builds. Compared to deployed inputs, each differs **only in GNU build-id payload**. project/userspace/compare.py zeroes only that note's descriptor, then compares every other ELF byte, including all segments, section tables, padding and file length. It does not compare only .text and does not forge the old ID.

Two source-built K4 roots, independently built kernels/modules/WPA binaries, and the same user-generated signing key produced byte-identical Alpine archives (`17082677…`). The new root does not equal the deployed archive: the user's signed package/index/key and rebuilt K4/WPA program metadata differ, and host module build/source symlinks are excluded. There is no claim that these differences are all build-id differences. All 73 package signatures, 312 ARM ELF, 199 dynamic dependencies and 23 modules passed; service syntax/dependency checks passed. PID1, real OpenRC boot and hardware acceptance were not run. Official Alpine distribution packages remain authenticated APK inputs; the separately required K4 BusyBox/Dropbear maintenance tools are built from source. This does not claim that every Alpine APK was rebuilt from source.

For deployment compatibility verification only, two separate runs using existing verified BusyBox base tar, deployed signed local WPA APK repository and matching module-tree metadata reproduced the deployed tar exactly: `d81de7ef896e51d384e2ca4589a5fea1f08778c5a366246b4afa757f37507e37`. This is **input replay, not a source-only public build**. The public entry does not consume that root tar or our signing private key.

Real apk tests with the user's key passed tag retention, untagged upgrade negative control and corrupted package rejection. 19 project and 5 userspace unittests passed, plus 15 barebox Python checks. Early root differences exposed a random temporary assembly FILE symbol and a host module build symlink; stable object names and excluding host symlinks resolved the two-build root comparison. The initial one-command trial supplied an experimental ZQ 8/4 fragment; production now retains stock 23/8. The final full one-command run is recorded separately in JSON; do not assume success until that result is present.
