# zqcal（RAM 诊断工具）

仅用于 K4 NT D01100 / LPDDR1。工具 overlay 基于 barebox v2026.09.0，例程在 OCRAM 内执行、DDR 自刷新期间测量，恢复原 ZQ 配置与 DDR 后校验；暂停 USB DMA，保存结果后恢复 USB，并维持看门狗。USB 串口可能断开，重连后读记录，不以丢输出判 DDR 失败。

在专用诊断 RAM 镜像中确认 watchdog/autoping 后：

```text
zqcal -b
zqcal -r
zqcal -n 1
zqcal -r
zqcal -n 16
zqcal -r
```

首轮必须 completed=1、status=0、done=444f4e45、checks=7、C层/内存校验通过，才继续16次。保存每次 PU/PD、众数、当前寄存器和校验。默认仅测量并恢复，不应用；`-a` 是显式高风险诊断，公共推荐流程不使用。镜像/source overlay 的导出尚须阶段7整理；不能把运行时内核模块当 barebox 命令。

本地样机原厂基准与1+16次测量均8/4、16/16一致，证明测量算法，不证明替换 DCD 在所有电源/温度下安全。上游 CTL75=0x817 对应PU=23/PD=8，CTL74装载字段采用+1编码（24/9）；本机8/4的对应值为 CTL75=0x408、装载字段9/5。完整七条装载顺序与CTL73/74控制位不可仅从读回值自行拼凑；手册字段编码与实物存在说明冲突，以核对过的实物序列为依据并记录边界。

用户决定按机器独立配置，不做自动校准。第二台先取得只读原厂基准，ROM测1次→16次→读回校验，保存私有机器标签，单独选择配置片段；通用默认不硬编码本机8/4。**目前开发继续上游23/8，8/4对照暂不部署**：8/4两次返回失败、23/8一次成功不足确定因果，四轮重复另排。不得在后台做校准、为测试深放电或写存储。
